## Authentication and Roles (Phase 2)

- Livewire class components: `app/Livewire/Auth/{Register,Login}.php` (validation rules in the
  component, rate limit on repeated failures in `Login`), `app/Livewire/Profile.php`,
  `app/Livewire/Admin/Dashboard.php` (placeholder until Phase 7), shared shell
  `resources/views/layouts/app.blade.php` with the `App\View\Components\AppLayout` class for
  plain Blade pages (Vendor welcome replaced by `resources/views/home.blade.php`).
- Routes (`routes/web.php`): `/register` + `/login` under `guest`, `/profile` + `POST /logout`
  (`LogoutController`, session invalidate + token regenerate) under `auth`, `/admin` group with
  `auth` + `role:admin,super_admin`.
- Middleware `app/Http/Middleware/EnsureRole.php` aliased as `role` in `bootstrap/app.php`;
  non-admin roles are sent home with the flash `error` rendered by the layout (FR-07).
- FR-03 rate limiting lives in the Login component via `RateLimiter` (5 failed attempts per
  minute, key = email + IP) so the throttle also covers Livewire update requests.
- FR-04: login redirects pull `url.intended` first (restores a requested protected page),
  then `admin.dashboard` for admin/super_admin and `home` for customers.
- FR-05: the session id is regenerated by the guard at login (tested) and invalidated at logout.
- Tests: `tests/Feature/{AuthRegistrationTest,AuthLoginTest,RoleAccessTest,ProfileTest}.php`
  covering every login/register/logout flow plus the three Key Test Criteria of section 5.1.

## Storefront (Phase 3)

- Livewire class components: `app/Livewire/CatalogPage.php` rendered by `/` and
  `/category/{slug}`, `app/Livewire/ProductDetail.php` rendered by `/products/{slug}`
  (`routes/web.php`, route names `home`, `categories.show`, `products.show`).
- CatalogPage holds all filter state in `#[Url]` properties (shareable links, FR-14):
  text search with `whereLike` over name + description (FR-11), category slug select,
  size/color chips validated against live options and mapped back to their canonical
  casing (FR-12), min/max price, sort `newest`/`price_low`/`price_high` with newest as
  the default (FR-13), `WithPagination` at 24 per page (FR-15), targeted `updated*`
  hooks reset pagination, plus a `clearFilters` action.
- Views: `resources/views/livewire/catalog-page.blade.php`,
  `resources/views/livewire/product-detail.blade.php`,
  `resources/views/components/product-card.blade.php` (FR-10 card: first image by
  sort_order, name, "starting from" base price, featured badge).
- ProductDetail: category breadcrumb (FR-17), color then size picker restricted to real
  SKUs (FR-18), final price through `ProductVariant::finalPrice()` (FR-19), stock line
  and a disabled add button for zero-stock SKUs (FR-20), product-level wishlist toggle
  (FR-21), and a 404 for inactive or missing slugs (FR-22). `addToCart` creates or merges
  the `CartItem` row with a `min(30, stock)` cap and sends guests to login while storing
  `url.intended` — groundwork for FR-25; the full CartManager lands in Phase 4.
- Helpers: `app/Support/Price.php` (`Price::format` for IDR), `ProductImage::url()` for
  public-disk gallery URLs.
- Tests: `tests/Feature/CatalogTest.php` and `tests/Feature/ProductDetailTest.php`
  cover all Key Test Criteria of sections 5.2 and 5.3.

## Cart and Wishlist (Phase 4)

- Livewire class components: `app/Livewire/CartManager.php` rendered by `/cart` and
  `app/Livewire/Wishlist.php` rendered by `/wishlist` (`routes/web.php`, both under
  `auth`, route names `cart` and `wishlist`).
- `CartItem::mergeAdd()` (`app/Models/CartItem.php`) is the single merge point for adds
  from the product page and the wishlist: the same SKU stays one row (FR-26) and the
  quantity is capped at `min(30, stock)` (FR-27).
- CartManager seeds typed quantity bindings on mount and clamps every edit through
  `setQty()`: below 1 lands on 1, above 30 or above stock clips with the explanatory
  message "Quantity clipped to {N}: only {S} left in stock." or "Quantity clipped to
  {N}, the per-SKU limit is 30." (FR-27); sold-out rows refuse edits outright.
- The subtotal and per-row totals re-render live from the typed binding
  (`wire:model.live="quantities.{{ $item->id }}"` + `updatedQuantities` hook) with no
  page load (FR-28). Rows whose stock shrank while parked are flagged ("Stock changed:
  only {S} left") and rows sold out show the remove hint (FR-29 flagging in the cart;
  the checkout-time block lands in Phase 5).
- Wishlist: saved products are product-level, not tied to an SKU
  (`app/Livewire/Wishlist.php`); move-to-cart takes the product's first variant with
  stock, merges through `mergeAdd`, then removes the save (FR-30). Products out of
  stock everywhere or no longer active stay saved with a notice.
- Header nav (`resources/views/layouts/app.blade.php`) links Catalog, Cart (with the
  summed quantity), and Wishlist for signed-in accounts; the product page confirms an
  add with "Added to cart: {label}.".
- Tests: `tests/Feature/CartManagerTest.php` (12) and `tests/Feature/WishlistTest.php`
  (6) cover FR-25..FR-31 flows and the three Key Test Criteria of section 5.4;
  `productWithVariants()` moved to `tests/Pest.php` as a shared helper.

## Checkout and Orders (Phase 5)

- `CheckoutForm` (`app/Livewire/CheckoutForm.php`) requires authentication, guides
  customers with an empty cart back to the catalog, supports pickup or courier
  delivery, validates the courier address, and previews the configured flat fee
  and optional note.
- `OrderService` (`app/Services/OrderService.php`) locks cart rows and SKU rows
  in a stable order, rechecks live stock, snapshots prices and variant labels,
  reserves stock, stores courier addresses, and clears the cart atomically.
- Customer order pages are scoped to the signed-in customer; cancellation is
  pending-only and restores reserved stock once. Tests cover stale-stock rollback,
  totals, order codes, ownership, and cancellation (`tests/Feature/CheckoutTest.php`,
  `tests/Feature/OrdersTest.php`).
- FR-38 is partial by design at this milestone: successful checkout leaves the
  order pending and opens its order page; the Snap transaction and payment redirect
  belong to Phase 6.
